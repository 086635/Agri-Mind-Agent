## 三、桥接问题详细分析

### 3.1 ❌ 严重：`/analyze` 端点请求格式不兼容

**问题描述**：

前端 PestAnalysisPage、FruitOutputAnalysisPage、PlantLodgingAnalysisPage、SoilEnvironmentAnalysisPage 四个页面以 **JSON 格式** 调用 `/analyze`：

```typescript
// 前端发送
POST /analyze
Content-Type: application/json
Body: { "analysis_type": "pest", "test_mode": true }
```

但后端 vision_server.py 的 `/analyze` 端点期望 **multipart/form-data** 格式的文件上传：

```python
# 后端期望
POST /analyze
Content-Type: multipart/form-data
Body: file=<二进制图片数据>
```

**影响**：这四个页面的分析功能**完全无法工作**，后端会返回 422 Unprocessable Entity 或 400 Bad Request。

**修复建议**：
- 方案A：前端改为选择图片后以 multipart/form-data 上传
- 方案B：后端新增 `/analyze/json` 端点，接受 JSON 格式的分析请求（指定分析类型，返回模拟/缓存结果）

---

### 3.2 ⚠️ 中等：`/chat` 端点字段名不匹配

**问题描述**：

SmartInteractionPage 的聊天请求发送 `message` 字段：

```typescript
// 前端发送
POST /chat
Body: { "message": "打开水泵", "context": "...", "chat_mode": "device" }
```

但后端 ai_gateway.py 的 `/chat` 端点期望 `command` 字段：

```python
# 后端期望
class CommandRequest(BaseModel):
    command: str  # 必填字段
```

**缓解**：超级网关在转发时做了字段适配（`message` → `command`），但仅当请求体包含 `message` 且不包含 `command` 时才生效。如果前端同时发送两个字段，适配不会触发。

**额外字段**：前端还发送了 `context`、`chat_mode`、`last_action` 字段，后端 `CommandRequest` 模型不包含这些字段，Pydantic 默认会忽略未知字段，不会报错但也不会使用。

**影响**：基本可工作，但 `context` 和 `chat_mode` 等增强信息被丢弃，AI 无法感知对话模式和上下文。

**修复建议**：后端 `CommandRequest` 模型增加可选字段：
```python
class CommandRequest(BaseModel):
    command: str
    context: Optional[str] = None
    chat_mode: Optional[str] = "expert"
    last_action: Optional[str] = None
```

---

### 3.3 ⚠️ 中等：`/analyze` 响应格式差异

**问题描述**：

SmartInteractionPage 的图像分析期望的响应格式与后端实际返回格式不一致：

```typescript
// 前端期望
{
  header: { status, message },
  data: {
    detections: [{ class, confidence, bbox }],
    objects: [{ name, confidence, severity }],
    summary: { total_objects, healthy, unhealthy, recommendations }
  }
}

// 后端实际返回 (VisionResponse)
{
  header: { status, latency_ms, device },
  data: {
    summary: { total_count, is_healthy },
    detections: [{ class_name, confidence, bbox }],
    analyzed_objects: [{ id, class_name, confidence, bbox, crop_url, rag_context, llm_analysis }],
    action_advice: "..."
  },
  report: { ... },
  annotated_url: "...",
  report_filename: "..."
}
```

**关键差异**：

| 字段 | 前端期望 | 后端实际 | 兼容性 |
|------|---------|---------|--------|
| 检测类别名 | `class` | `class_name` | ❌ 不匹配 |
| 检测对象列表 | `objects` | `analyzed_objects` | ❌ 不匹配 |
| 摘要格式 | `{ total_objects, healthy, unhealthy }` | `{ total_count, is_healthy }` | ❌ 不匹配 |
| header.message | 存在 | 不存在（改为 latency_ms） | ⚠️ 缺失 |
| header.latency_ms | 不期望 | 存在 | ✅ 多余字段被忽略 |
| report | 不期望 | 存在 | ✅ 多余字段被忽略 |

**影响**：前端解析后端响应时，`class`/`objects`/`total_objects` 等字段会为 `undefined`，导致检测结果显示异常。

**修复建议**：前端适配后端实际响应格式，或后端在响应中同时提供两种字段名。

---

### 3.4 ⚠️ 中等：`/analytics/dashboard` 响应格式差异

**问题描述**：

前端期望的传感器汇总格式与后端实际返回格式不一致：

```typescript
// 前端期望 (DashboardSensorSummary)
{
  sensor_summary: {
    temperature: { current: 25.3, avg_24h: 24.1, min_24h: 20.0, max_24h: 30.0 },
    humidity: { current: 60.0, ... },
    ...
  }
}

// 后端实际返回
{
  sensor_summary: {
    "temperature": [{ "device": "sensor_temp_01", "latest": "25.3", "avg": 24.1 }],
    "humidity": [{ "device": "sensor_humid_01", "latest": "60.0", "avg": 62.0 }],
    ...
  }
}
```

**差异**：
- 前端期望 `{ current, avg_24h, min_24h, max_24h }` 对象
- 后端返回 `[{ device, latest, avg }]` 数组

**影响**：仪表盘传感器数值显示可能异常，前端需要做格式转换。
