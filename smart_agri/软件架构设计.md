## 第一部分：概要设计

### 1.1 系统概述

智慧农业 AI 网关系统是一个完整的 **Human-in-the-Loop (HITL)** 经验学习平台，实现了从传感器数据采集、AI 决策分析、设备控制到经验知识沉淀的完整闭环。系统采用微服务架构，通过超级网关统一对外提供服务。

#### 核心价值

├─────────────────────────────────────────────────────────────────────────────┤

│   农户操作 ──> 意图识别 ──> 风险评估 ──> 执行/挂起 ──> 用户反馈              │
│       │                                                      │              │
│       │                                                      ▼              │

### 1.2 设计目标

| 目标 | 描述 |
|------|------|
| **智能化决策** | 基于 LLM 和 RAG 技术实现自然语言交互和智能决策 |
| **经验沉淀** | 通过 HITL 机制将农户口语化经验转化为可复用的结构化规则 |
| **视觉感知** | 集成 YOLOv11 目标检测和 Qwen-VL 视觉分析能力 |
| **设备控制** | 通过 MQTT 协议实现实时设备控制和状态同步 |
| **高可用性** | 微服务架构支持独立部署和水平扩展 |

### 1.3 技术选型

#### 1.3.1 后端技术栈

| 层次 | 技术选型 | 说明 |
|------|---------|------|
| **Web 框架** | FastAPI | 高性能异步 Python Web 框架 |
| **ORM** | SQLAlchemy 2.0 | 支持异步操作的 Python ORM |
| **数据库** | PostgreSQL | 关系型数据库，支持 JSON 和向量扩展 |
| **缓存** | Redis | 会话存储、分布式锁、消息队列 |
| **向量数据库** | ChromaDB | 本地向量数据库，支持 RAG 检索 |
| **工作流引擎** | LangGraph | 状态图工作流引擎，支持检查点持久化 |
| **消息队列** | MQTT (EMQX) | 轻量级物联网消息协议 |

#### 1.3.2 AI 技术栈

| 能力 | 技术选型 | 说明 |
|------|---------|------|
| **LLM 服务** | AnythingLLM | 本地部署的大语言模型服务 |
| **视觉模型** | YOLOv11 | 目标检测模型 |
| **视觉分析** | Qwen-VL-Plus | 阿里云视觉语言模型 |
| **嵌入模型** | BAAI/bge-m3 | 多语言向量嵌入模型 |

#### 1.3.3 开发工具

| 工具 | 用途 |
|------|------|
| **Pydantic** | 数据验证和序列化 |
| **httpx** | 异步 HTTP 客户端 |
| **uvicorn** | ASGI 服务器 |

### 2.1 模块划分

#### 2.1.1 模块总览

| 模块名称 | 文件/目录 | 端口 | 核心职责 |
|---------|----------|------|---------|
| **超级网关模块** | `super_gateway.py` | 9000 | 统一入口、请求路由、健康检查 |

#### 2.1.2 超级网关模块 (super_gateway.py)

**功能描述：**
- 统一 API 入口，对外暴露单一端口
- 请求路由转发到下游微服务
- 健康检查和服务状态监控
- CORS 跨域处理

**核心组件：**

```python
# 路由配置
路由规则:
  - /chat, /voice_cmd, /stats/* → AI 大脑 (localhost:8001)
  - /analyze, /crops/{filename} → 视觉推理 (localhost:8004)
  - /monitor, /control → 业务逻辑 (localhost:8003)
  - /dify/run → Dify 工作流 (localhost/v1)
  - /health → 健康检查
```

**关键类：**

| 类名 | 职责 |
|------|------|
| `FastAPI` | Web 应用框架 |
| `httpx.AsyncClient` | 异步 HTTP 客户端，用于请求转发 |

#### 2.1.3 AI 大脑模块 (ai_gateway.py)

**功能描述：**
- 集成 AnythingLLM 实现智能对话

- 语音指令解析和意图识别
- 传感器数据查询和上下文构建

**核心组件：**

| 组件 | 说明 |
|------|------|
| `SmartFarmProcessor` | 意图处理器，解析 AI 返回的控制指令 |
| `mqtt.Client` | MQTT 客户端，连接 broker.emqx.io |
| `call_anything_llm()` | 调用 AnythingLLM API 的异步函数 |

#### 2.2.4 业务逻辑接口 (server/main.py)

| 接口路径 | 方法 | 请求体 | 功能 |
|---------|------|--------|------|
| `/ping` | GET | - | 健康检查 |
| `/api/v1/telemetry` | POST | `TelemetryPayload` | 接收传感器数据 |
| `/api/v1/chat` | POST | `ChatRequest` | Agent 对话 |
| `/api/v1/experience/quantize` | POST | `ExperienceQuantizationRequest` | 经验量化 |
| `/api/v1/experience/refine` | POST | `HumanInterventionRequest` | 人工干预经验提取 |
| `/api/v1/execute` | POST | `ExecuteRequest` | 执行操作（高风险挂起） |
| `/api/v1/confirm` | POST | `ConfirmRequest` | 确认挂起操作 |
| `/api/v1/logic/history` | GET | - | 获取逻辑历史 |

**请求模型定义：**

```python
class TelemetryPayload(BaseModel):
    device_id: str
    sensor_type: str
    value: float

class ChatRequest(BaseModel):
    message: str
    thread_id: Optional[str] = None

class ExperienceQuantizationRequest(BaseModel):
    human_reasoning: str
    actor_id: str = "Human"
    device_id: str = None
    batch_id: str = None

class ExecuteRequest(BaseModel):
    action_type: str
    target_device: str
    value: Any
    reasoning: str
    env_snapshot: Optional[dict] = None

class ConfirmRequest(BaseModel):
    session_id: str
    feedback_type: str  # confirm_logic | adjust_logic | new_logic
    selected_logic_id: Optional[int] = None
    adjustments: Optional[dict] = None
    new_reasoning: Optional[str] = None
```
