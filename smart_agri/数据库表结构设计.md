## 1. 数据库概述

### 1.1 连接配置

```python
# 异步连接 URL
ASYNC_DATABASE_URL = "postgresql+asyncpg://postgres:password@localhost:5432/agri_ai"

# 同步连接 URL
SYNC_DATABASE_URL = "postgresql://postgres:password@localhost:5432/agri_ai"
```

### 1.2 命名规范

| 规范项 | 说明 |
|--------|------|
| 表名 | 小写下划线命名，如 `raw_environmental_readings` |
| 字段名 | 小写下划线命名，如 `device_id` |
| 主键 | 统一使用 `id` 或 `{table}_id` |
| 外键 | `{关联表}_id` 格式 |
| 索引 | `idx_{表名}_{字段名}` 格式 |
| 唯一约束 | `uk_{表名}_{字段组合}` 格式 |

### 1.3 数据层次架构

## 2. 表结构详细设计

### 2.1 原始环境热数据表 (raw_environmental_readings)

**表说明：** 存储 L1 层传感器原始数据，高频写入。

| 字段名 | 数据类型 | 可空 | 默认值 | 说明 |
|--------|---------|------|--------|------|
| `id` | BIGINT | NO | AUTO | 主键 ID |
| `timestamp` | TIMESTAMP | NO | NOW() | 采样时间戳 |
| `device_id` | VARCHAR(64) | NO | - | 设备 ID |
| `batch_id` | VARCHAR(64) | YES | - | 批次 ID |
| `sensor_type` | VARCHAR(32) | NO | - | 传感器类型 (air_temp, soil_npk 等) |
| `raw_value` | NUMERIC(10,4) | NO | - | 原始采样值 |
| `reliability_score` | NUMERIC(5,4) | YES | 1.0000 | 数据可靠性评分 (0-1) |
| `experiment_group` | VARCHAR(32) | YES | 'CONTROL' | 实验分组 |
| `created_at` | TIMESTAMP | NO | NOW() | 创建时间 |

**索引：**

```sql
CREATE INDEX idx_device_time ON raw_environmental_readings(device_id, timestamp);
CREATE INDEX idx_raw_timestamp ON raw_environmental_readings(timestamp);
```

**SQL 建表语句：**

```sql
CREATE TABLE raw_environmental_readings (
    id BIGSERIAL PRIMARY KEY,
    timestamp TIMESTAMP NOT NULL DEFAULT NOW(),
    device_id VARCHAR(64) NOT NULL,
    batch_id VARCHAR(64),
    sensor_type VARCHAR(32) NOT NULL,
    raw_value NUMERIC(10,4) NOT NULL,
    reliability_score NUMERIC(5,4) DEFAULT 1.0000,
    experiment_group VARCHAR(32) DEFAULT 'CONTROL',
    created_at TIMESTAMP NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_device_time ON raw_environmental_readings(device_id, timestamp);
```

### 2.2 二级数据分析表 (agri_analytical_metrics)

**表说明：** 存储 L2 层分析指标数据，用于农业看板展示。

| 字段名 | 数据类型 | 可空 | 默认值 | 说明 |
|--------|---------|------|--------|------|
| `id` | BIGINT | NO | AUTO | 主键 ID |
| `batch_id` | VARCHAR(64) | NO | - | 批次 ID |
| `device_id` | VARCHAR(64) | NO | - | 设备 ID |
| `strategy_id` | VARCHAR(64) | YES | - | 策略 ID |
| `record_date` | DATE | NO | - | 记录日期 |
| `par_val_umol` | NUMERIC(10,2) | YES | - | 光合有效辐射 (μmol/m²/s) |
| `dli_daily_mol` | NUMERIC(10,2) | YES | - | 日光积分 (mol/m²/d) |
| `carbon_sink_rate_g_hr` | NUMERIC(10,4) | YES | - | 碳汇速率 (g/hr) |
| `vpd_val_kpa` | NUMERIC(10,4) | YES | - | 蒸气压亏缺 (kPa) |
| `nutrient_consumption_rate_mg_hr` | NUMERIC(10,2) | YES | - | 养分消耗率 (mg/hr) |
| `current_accumulated_gdd_c` | NUMERIC(10,2) | YES | - | 累计积温 (℃·d) |
| `lue_score_pct` | NUMERIC(5,2) | YES | - | 光利用率评分 (%) |
| `energy_optimization_index` | NUMERIC(10,4) | YES | - | 能耗优化指数 |
| `r_squared_val` | NUMERIC(5,4) | YES | - | R² 拟合度 |
| `completion_rate_pct` | NUMERIC(5,2) | YES | - | 目标完成率 (%) |
| `data_status` | VARCHAR(32) | YES | 'VALID' | 数据状态 |

**约束：**

```sql
UNIQUE (batch_id, device_id, record_date)  -- 防止重复数据
```

**索引：**

```sql
CREATE UNIQUE INDEX uk_batch_device_date ON agri_analytical_metrics(batch_id, device_id, record_date);
CREATE INDEX idx_device_date ON agri_analytical_metrics(device_id, record_date);
CREATE INDEX idx_batch_id ON agri_analytical_metrics(batch_id);
```

**SQL 建表语句：**

```sql
CREATE TABLE agri_analytical_metrics (
    id BIGSERIAL PRIMARY KEY,
    batch_id VARCHAR(64) NOT NULL,
    device_id VARCHAR(64) NOT NULL,
    strategy_id VARCHAR(64),
    record_date DATE NOT NULL,
    par_val_umol NUMERIC(10,2),
    dli_daily_mol NUMERIC(10,2),
    carbon_sink_rate_g_hr NUMERIC(10,4),
    vpd_val_kpa NUMERIC(10,4),
    nutrient_consumption_rate_mg_hr NUMERIC(10,2),
    current_accumulated_gdd_c NUMERIC(10,2),
    lue_score_pct NUMERIC(5,2),
    energy_optimization_index NUMERIC(10,4),
    r_squared_val NUMERIC(5,4),
    completion_rate_pct NUMERIC(5,2),
    data_status VARCHAR(32) DEFAULT 'VALID',
    CONSTRAINT uk_batch_device_date UNIQUE (batch_id, device_id, record_date)
);

CREATE INDEX idx_device_date ON agri_analytical_metrics(device_id, record_date);
CREATE INDEX idx_batch_id ON agri_analytical_metrics(batch_id);
```

### 2.3 设备数字孪生表 (device_digital_twin_status)

**表说明：** 存储 L3 层设备状态和健康诊断数据。

| 字段名 | 数据类型 | 可空 | 默认值 | 说明 |
|--------|---------|------|--------|------|
| `id` | BIGINT | NO | AUTO | 主键 ID |
| `device_id` | VARCHAR(64) | NO | - | 设备 ID (唯一) |
| `rated_power_w` | NUMERIC(10,2) | NO | - | 额定功率 (W) |
| `runtime_total_hrs` | NUMERIC(12,2) | YES | 0.00 | 累计运行时间 (小时) |
| `on_off_cycles_count` | BIGINT | YES | 0 | 启停次数 |
| `duty_cycle_ratio_pct` | NUMERIC(5,2) | YES | 0.00 | 占空比 (%) |
| `device_thermal_slope` | NUMERIC(10,4) | YES | - | 热力响应斜率 |
| `action_latency_ms` | BIGINT | YES | - | 指令响应延迟 (ms) |
| `response_consistency_r2` | NUMERIC(5,4) | YES | - | 响应一致性 R² |
| `failure_probability_pct` | NUMERIC(5,2) | YES | 0.00 | 故障概率 (%) |
| `last_maintenance_date` | TIMESTAMP | YES | - | 上次维护日期 |
| `updated_at` | TIMESTAMP | NO | NOW() | 更新时间 |

**约束：**

```sql
UNIQUE (device_id)  -- 设备 ID 唯一
```

**SQL 建表语句：**

```sql
CREATE TABLE device_digital_twin_status (
    id BIGSERIAL PRIMARY KEY,
    device_id VARCHAR(64) NOT NULL UNIQUE,
    rated_power_w NUMERIC(10,2) NOT NULL,
    runtime_total_hrs NUMERIC(12,2) DEFAULT 0.00,
    on_off_cycles_count BIGINT DEFAULT 0,
    duty_cycle_ratio_pct NUMERIC(5,2) DEFAULT 0.00,
    device_thermal_slope NUMERIC(10,4),
    action_latency_ms BIGINT,
    response_consistency_r2 NUMERIC(5,4),
    failure_probability_pct NUMERIC(5,2) DEFAULT 0.00,
    last_maintenance_date TIMESTAMP,
    updated_at TIMESTAMP NOT NULL DEFAULT NOW()
);
```

### 2.5 策略风险阈值表 (policy_risk_thresholds)

**表说明：** 存储动态调整的控制策略阈值，支持行级锁和乐观锁。

| 字段名 | 数据类型 | 可空 | 默认值 | 说明 |
|--------|---------|------|--------|------|
| `strategy_id` | BIGINT | NO | AUTO | 主键 ID |
| `metric_name` | VARCHAR(64) | NO | - | 指标名称 |
| `threshold_logic` | JSON | NO | - | JSON 格式的复杂逻辑配置 |
| `priority` | INTEGER | NO | 1 | 优先级 (越大越高) |
| `version` | INTEGER | NO | 1 | 乐观锁版本号 |
| `created_at` | TIMESTAMP | NO | NOW() | 创建时间 |
| `updated_at` | TIMESTAMP | NO | NOW() | 更新时间 |

**索引：**

```sql
CREATE INDEX idx_metric_priority ON policy_risk_thresholds(metric_name, priority);
```

**threshold_logic JSON 结构示例：**

```json
{
    "condition": "weather_forecast == 'rain'",
    "action": "increase_threshold",
    "value": 5.0,
    "unit": "pct",
    "reasoning": "雨天需增加灌溉阈值防止积水"
}
```

**SQL 建表语句：**

```sql
CREATE TABLE policy_risk_thresholds (
    strategy_id BIGSERIAL PRIMARY KEY,
    metric_name VARCHAR(64) NOT NULL,
    threshold_logic JSON NOT NULL,
    priority INTEGER NOT NULL DEFAULT 1,
    version INTEGER NOT NULL DEFAULT 1,
    created_at TIMESTAMP NOT NULL DEFAULT NOW(),
    updated_at TIMESTAMP NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_metric_priority ON policy_risk_thresholds(metric_name, priority);
```

### 2.6 动作审计表 (agent_action_audit)

**表说明：** 记录所有人工和智能体的操作干预，支持 HITL 工作流。

| 字段名 | 数据类型 | 可空 | 默认值 | 说明 |
|--------|---------|------|--------|------|
| `audit_id` | BIGINT | NO | AUTO | 主键 ID |
| `actor_id` | VARCHAR(64) | NO | - | 操作者 ID (Human/Agent) |
| `action_type` | VARCHAR(128) | NO | - | 操作类型 |
| `reasoning_context` | TEXT | NO | - | 操作理由 |
| `expected_delta` | JSON | YES | - | 预期变化 |
| `actual_delta` | JSON | YES | - | 实际变化 |
| `skill_invoked` | VARCHAR(128) | YES | - | 调用的 Skill 接口 |
| `execution_status` | VARCHAR(32) | YES | 'Pending' | 队列状态 |
| `is_experience_source` | BOOLEAN | YES | FALSE | 是否被提取为知识 |
| `status` | ENUM | NO | 'executed' | 动作状态 |
| `session_id` | VARCHAR(64) | YES | - | 会话 ID |
| `action_set_hash` | VARCHAR(128) | YES | - | 操作组合哈希指纹 |
| `matched_logic_id` | BIGINT | YES | - | 匹配的 RAG 规则 ID |
| `user_feedback` | JSON | YES | - | 用户反馈详情 |
| `env_snapshot_ref` | JSON | YES | - | 环境快照 |
| `created_at` | TIMESTAMP | NO | NOW() | 创建时间 |

**状态枚举 (ActionStatus)：**

| 值 | 说明 |
|----|------|
| `executed` | 已执行 |
| `pending_logic_confirmation` | 待逻辑确认 |
| `rejected` | 已拒绝 |
| `executed_without_feedback` | 已执行无反馈 |

**索引：**

```sql
CREATE INDEX idx_actor_created ON agent_action_audit(actor_id, created_at);
CREATE INDEX idx_action_type ON agent_action_audit(action_type);
CREATE INDEX idx_experience_source ON agent_action_audit(is_experience_source);
CREATE INDEX idx_status ON agent_action_audit(status);
CREATE INDEX idx_session_id ON agent_action_audit(session_id);
CREATE INDEX idx_action_set_hash ON agent_action_audit(action_set_hash);
CREATE INDEX idx_matched_logic_id ON agent_action_audit(matched_logic_id);
```

**SQL 建表语句：**

```sql
-- 创建枚举类型
CREATE TYPE actionstatus AS ENUM (
    'executed',
    'pending_logic_confirmation',
    'rejected',
    'executed_without_feedback'
);

CREATE TABLE agent_action_audit (
    audit_id BIGSERIAL PRIMARY KEY,
    actor_id VARCHAR(64) NOT NULL,
    action_type VARCHAR(128) NOT NULL,
    reasoning_context TEXT NOT NULL,
    expected_delta JSON,
    actual_delta JSON,
    skill_invoked VARCHAR(128),
    execution_status VARCHAR(32) DEFAULT 'Pending',
    is_experience_source BOOLEAN DEFAULT FALSE,
    status actionstatus NOT NULL DEFAULT 'executed',
    session_id VARCHAR(64),
    action_set_hash VARCHAR(128),
    matched_logic_id BIGINT REFERENCES policy_risk_thresholds(strategy_id),
    user_feedback JSON,
    env_snapshot_ref JSON,
    created_at TIMESTAMP NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_actor_created ON agent_action_audit(actor_id, created_at);
CREATE INDEX idx_action_type ON agent_action_audit(action_type);
CREATE INDEX idx_experience_source ON agent_action_audit(is_experience_source);
CREATE INDEX idx_status ON agent_action_audit(status);
CREATE INDEX idx_session_id ON agent_action_audit(session_id);
CREATE INDEX idx_action_set_hash ON agent_action_audit(action_set_hash);
CREATE INDEX idx_matched_logic_id ON agent_action_audit(matched_logic_id);
```

### 2.7 逻辑嫁接日志表 (logic_grafting_logs)

| 字段名 | 数据类型 | 可空 | 默认值 | 说明 |

| `new_reasoning` | TEXT | YES | - | 新的推理描述 |
| `confidence_score` | NUMERIC(5,2) | YES | - | 确认坚决程度 (0-100) |

**反馈类型说明：**

| 值 | 说明 |
|----|------|
| `confirm_logic` | 确认逻辑 |
| `adjust_logic` | 调整逻辑 |

```sql
CREATE TABLE logic_grafting_logs (
```

```sql
-- 查询设备最新状态（使用索引 idx_device_time）
SELECT * FROM raw_environmental_readings 
WHERE device_id = 'device_001' 
ORDER BY timestamp DESC LIMIT 1;

-- 查询批次分析数据（使用唯一索引 uk_batch_device_date）
SELECT * FROM agri_analytical_metrics

SELECT * FROM agent_action_audit
```

### A. 完整建表 SQL 脚本

```sql
-- ============================================
-- 智慧农业 AI 网关系统 - 完整建表脚本
-- ============================================

-- 1. 创建枚举类型
CREATE TYPE actionstatus AS ENUM (
    'executed',
    'pending_logic_confirmation',
    'rejected',
    'executed_without_feedback'
);

-- 2. 创建原始环境热数据表
CREATE TABLE raw_environmental_readings (
    id BIGSERIAL PRIMARY KEY,
    timestamp TIMESTAMP NOT NULL DEFAULT NOW(),
    device_id VARCHAR(64) NOT NULL,
    batch_id VARCHAR(64),
    sensor_type VARCHAR(32) NOT NULL,
    raw_value NUMERIC(10,4) NOT NULL,
    reliability_score NUMERIC(5,4) DEFAULT 1.0000,
    experiment_group VARCHAR(32) DEFAULT 'CONTROL',
    created_at TIMESTAMP NOT NULL DEFAULT NOW()
);
CREATE INDEX idx_device_time ON raw_environmental_readings(device_id, timestamp);

-- 3. 创建二级数据分析表
CREATE TABLE agri_analytical_metrics (
    id BIGSERIAL PRIMARY KEY,
    batch_id VARCHAR(64) NOT NULL,
    device_id VARCHAR(64) NOT NULL,
    strategy_id VARCHAR(64),
    record_date DATE NOT NULL,
    par_val_umol NUMERIC(10,2),
    dli_daily_mol NUMERIC(10,2),
    carbon_sink_rate_g_hr NUMERIC(10,4),
    vpd_val_kpa NUMERIC(10,4),
    nutrient_consumption_rate_mg_hr NUMERIC(10,2),
    current_accumulated_gdd_c NUMERIC(10,2),
    lue_score_pct NUMERIC(5,2),
    energy_optimization_index NUMERIC(10,4),
    r_squared_val NUMERIC(5,4),
    completion_rate_pct NUMERIC(5,2),
    data_status VARCHAR(32) DEFAULT 'VALID',
    CONSTRAINT uk_batch_device_date UNIQUE (batch_id, device_id, record_date)
);
CREATE INDEX idx_device_date ON agri_analytical_metrics(device_id, record_date);
CREATE INDEX idx_batch_id ON agri_analytical_metrics(batch_id);

-- 4. 创建设备数字孪生表
CREATE TABLE device_digital_twin_status (
    id BIGSERIAL PRIMARY KEY,
    device_id VARCHAR(64) NOT NULL UNIQUE,
    rated_power_w NUMERIC(10,2) NOT NULL,
    runtime_total_hrs NUMERIC(12,2) DEFAULT 0.00,
    on_off_cycles_count BIGINT DEFAULT 0,
    duty_cycle_ratio_pct NUMERIC(5,2) DEFAULT 0.00,
    device_thermal_slope NUMERIC(10,4),
    action_latency_ms BIGINT,
    response_consistency_r2 NUMERIC(5,4),
    failure_probability_pct NUMERIC(5,2) DEFAULT 0.00,
    last_maintenance_date TIMESTAMP,
    updated_at TIMESTAMP NOT NULL DEFAULT NOW()
);

-- 5. 创建 ESG 价值核算表
CREATE TABLE esg_value_realization (
    id BIGSERIAL PRIMARY KEY,
    batch_id VARCHAR(64) NOT NULL,
    device_id VARCHAR(64) NOT NULL,
    record_date DATE NOT NULL,
    biomass_carbon_sequestration_g NUMERIC(12,2) DEFAULT 0.00,
    operational_carbon_footprint_g NUMERIC(12,2) DEFAULT 0.00,
    net_zero_ratio NUMERIC(10,4),
    water_saved_liters NUMERIC(10,2) DEFAULT 0.00,
    energy_efficiency_ratio NUMERIC(10,4),
    cost_reduction_amount_cny NUMERIC(10,2) DEFAULT 0.00,
    CONSTRAINT uk_esg_daily UNIQUE (batch_id, device_id, record_date)
);

-- 6. 创建策略风险阈值表
CREATE TABLE policy_risk_thresholds (
    strategy_id BIGSERIAL PRIMARY KEY,
    metric_name VARCHAR(64) NOT NULL,
    threshold_logic JSON NOT NULL,
    priority INTEGER NOT NULL DEFAULT 1,
    version INTEGER NOT NULL DEFAULT 1,
    created_at TIMESTAMP NOT NULL DEFAULT NOW(),
    updated_at TIMESTAMP NOT NULL DEFAULT NOW()
);
CREATE INDEX idx_metric_priority ON policy_risk_thresholds(metric_name, priority);

-- 7. 创建动作审计表
CREATE TABLE agent_action_audit (
    audit_id BIGSERIAL PRIMARY KEY,

    execution_status VARCHAR(32) DEFAULT 'Pending',
    is_experience_source BOOLEAN DEFAULT FALSE,
    status actionstatus NOT NULL DEFAULT 'executed',
    session_id VARCHAR(64),
    action_set_hash VARCHAR(128),
    matched_logic_id BIGINT REFERENCES policy_risk_thresholds(strategy_id),
    user_feedback JSON,
    env_snapshot_ref JSON,
    created_at TIMESTAMP NOT NULL DEFAULT NOW()
);
CREATE INDEX idx_actor_created ON agent_action_audit(actor_id, created_at);
CREATE INDEX idx_action_type ON agent_action_audit(action_type);
CREATE INDEX idx_experience_source ON agent_action_audit(is_experience_source);
CREATE INDEX idx_status ON agent_action_audit(status);
CREATE INDEX idx_session_id ON agent_action_audit(session_id);
CREATE INDEX idx_action_set_hash ON agent_action_audit(action_set_hash);
CREATE INDEX idx_matched_logic_id ON agent_action_audit(matched_logic_id);

CREATE TABLE logic_grafting_logs (

);
```
